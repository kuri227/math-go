## 1. 目指す体験

高専祭・文化祭で、初めて触る来場者が数学へ手書きで挑戦する、ローカル動作のソロゲームです。観客も問題と回答過程を見て楽しめることを目指します。

中心は「モニターで問題を見る → 液タブに答えを書く → 認識を確認して提出 → モニターで結果を見る」。入力の便利さだけを追求して液タブですべて完結させるのではなく、**問題と用紙の分離、視線の移動そのものを遊びにします。** 対戦・遠隔マルチプレイは目的に含めません。

次期構成では、モニターは問題・回答筆跡・正誤演出・結果のステージ、液タブは設定から再プレイまでのコントローラーです。ユーザー操作の集約と、ゲーム内容の集約は別です。液タブに問題・正答・解説を複製しません。

学習データ収集はテストプレイの任意機能であり、展示参加の必須条件にしません。展示の楽しさとモデル改善のための作業を混同しません。

## 3. 現在のゲームとデータの流れ

### プレイ

```text
現行：Displayでモード・問題選択 → ガイド → 開始
       → writing → recognizing → preview → judging
           ↑           失敗時は復帰          │
           └── 本番の誤答・書き直し ─────────┘
       → 正解／時間切れのresult → 次問またはfinished

次期：Controllerで選択 → 両画面ガイド → 準備同期 → 開始予告
       → 同じゲーム進行（DisplayのSessionが正本）
       ＋ Controllerの回答筆跡だけをDisplayへ複製
       ＋ Controller内の独立メモ（非送信）
```

`Session.ts` に`countdown`状態を追加し、Controllerの用紙準備通知までは予告も時計も開始しない契約にしました。切断時は予告を取り消してガイドへ戻ります。

本番は誤答なら同じ問題を継続し、正答を公開しません。正解・時間切れ後は正答と解説を確認します。残機0、全問完了、手動中断を区別して終了します。無制限テストでは問題を再試行できます。

### 認識・採点・保存・学習は別処理

1. Controllerが回答のCanvasからcrop済みPNGを作り、ローカル認識APIへ送ります。
2. TexTellerがLaTeXを返し、入力した本人が画像と読み取りを比較します。
3. 確認後に採点します。現在は登録正答候補との表記照合であり、任意の数式同値判定ではありません。
4. テスト時だけ、同意・画像に忠実な人手転記を付けて学習候補を保存できます。算数としての正誤と転記の正しさは別です。
5. 学習担当者が重複・品質・筆者分割をレビューし、使用台帳を確認して追加学習します。評価セットや使用済み画像を再投入しません。
6. 新しい重みは候補モデルです。保存しただけで学習せず、学習しただけで稼働モデルも置換しません。

次期の表示用筆跡同期は1〜6とは別経路です。プレビュー用の認識、回答の提出、データ保存を筆跡の受信だけで実行してはいけません。メモはこの経路すべてから除外する設計です。

## 4. 技術を選んだ理由と代償

以下は現行コードと履歴から整理した理由です。過去の文書に当時明記されていないものは、現在の構成に対する評価として扱います。

| 選択 | 解決すること・意図 | 代償・再検討条件 |
|---|---|---|
| TypeScript＋Vite＋DOM | 型付きの状態・通信境界、ビルド再現、文章・フォームの自然な配置。旧Phaserの固定座標とDOMの二重調整を減らす | DOM構築・更新規律は必要。React等への移行自体を改善目的にしない |
| KaTeXをローカル同梱 | 数式組版、外部CDNなしの展示。解釈不能な式は文字で残す | 長式のfit・スクロール設計が必要。数学的正しさを検証するライブラリーではない |
| 独立Canvas＋Pointer Events | ペン・マウスの入力、PNG生成、筆圧・時刻付き筆跡、undoを認識と分離 | 複数用紙・同期・resizeは独自契約が必要。手書きの完全な非ポインター代替は未提供 |
| DisplayのSessionを唯一の進行正本にする | 時計・残機・問題番号・採点の二重管理を防ぐ | Displayの再読み込みからのゲーム復元は別問題。Controllerの操作権とは切り離す |
| 同一PCのWebSocket＋PairHub | タブのheartbeatタイマーに依存しない接続所有、切断・重複接続・再接続の扱い | 別PC対応・永続サーバーセッションではない。再接続しても操作を無条件再送しない |
| FastAPI＋Pythonモデルワーカー | 画像検証/APIと重い推論を分離。モデル常駐による再ロード回避、異常時の破棄 | プロセス・待ち行列・上限時間の管理が必要。複数サーバーworkers運用は想定外 |
| モデル別venv・CPU/GPU別導入 | 依存衝突を減らし、PCに合う推論環境を選ぶ。展示はTexTeller、比較のみUniMERNet | 初回取得・ディスク容量が必要。NVIDIAドライバー互換性の確認は残る |
| JSON問題バンク | 516問の変更をGit差分でレビューし、DBサーバーなしで配布 | 同時編集・分散書き込みに弱い。ファイルキャッシュと書込検証が必要 |
| SQLite学習台帳＋OS排他 | 画像の使用履歴を一箇所で保持し、並行学習・中断後の再消費を防ぐ | データを消してやり直す運用は不可。バックアップと停止確認が必要 |
| git clone / pull＋セットアップスクリプト | 同じソース・依存設定を展示PCへ再現し、目的別履歴を追える | cloneだけでは実行準備は終わらない。Python・Node・pnpm、初回のモデル取得とビルドが必要 |

筆跡同期は通信版v4で、縦横比付きの正規化座標snapshotを既存WebSocketへ追加しました。ローカル描画は送信を待たず、最大12,000点、約40ms単位で送信し、再接続時は全体を再送します。PNG連続送信や動画配信は採用していません。差分方式ではなく全体snapshotを選んだため、実機でメッセージ量・p95遅延・長時間メモリを測定し、上限内で成立しない場合は差分方式を再検討します。

## 6. 現状の課題と実装順

既に修正した不具合と、まだ測定していないリスクと、新機能の不足を区別します。過去の監査の全件を現在の未修正一覧として再掲しません。

| 優先度 | 差分・課題 | 次に行うこと／完了条件 |
|---|---|---|
| P0 | 設定・開始・終了後の操作が液タブで完結していない | 全遷移をControllerから操作。Displayのゲーム進行正本を維持 |
| P0 | 画面準備の同期なし。最初の問題がガイドのsnapshotに存在する | 準備状態と表示用データを分離。開始前に問題を描画せず、入力可能と計時を連動 |
| P0 | 生筆跡の同期がない | 回答だけを座標同期。undo・clear・再接続・旧問題拒否・過負荷を試験 |
| P1 | メモ機能なし | 独立履歴・回答のみ認識。次問クリア、誤答時保持、再読込時の喪失を説明 |
| P1 | 問題と回答コピーを同居させるモニターレイアウト未検証 | 短い数字・長文・分数・行列、横長・縦長・低い画面で比較。問題の可読性優先 |
| P1 | ペン実機・表示倍率・スリープ復帰・長時間運転の証拠不足 | 展示PCと液タブでリハーサル。実測値・失敗・未実施を記録 |
| P1 | 認識精度とCPU待ち時間 | 公開16枚のCPU計測は約2秒中央値でも一般保証しない。代表問題・実筆で再評価 |
| P1 | 全516問の体験適合性未確認 | 問題の正しさ、20秒の難度、表記照合での誤判定を人手確認 |
| P2 | 任意の数学的同値判定、完全なキーボード代替、Display再読込後の復元 | 別の設計判断が必要。今回の機能と抱き合わせない |

操作移管、開始同期、筆跡同期、メモの実装後は、U01〜U12を「代表状態をまとめて観察→一括修正→1回だけ再確認」の有限なレビューで検証します。自動テスト、実API、両画面ブラウザー、実機ペン、CPU/GPU、遅延測定の証拠境界を分け、未検証を機能合格として扱いません。
