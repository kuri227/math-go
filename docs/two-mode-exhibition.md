# 本番体験・テストプレイの操作とデータ収集

2026-10-16の現行仕様。旧3コース・時間切れ即終了の仕様に優先する。

## 本番体験

- 選択レベルの「確認済み」かつ「本番候補」から7問を重複なしで抽選。カテゴリ・区分を分散し、rank順に並べる。
- 1問20秒・残機3。誤答では進まず、時間内なら何度でも回答可能。誤答・認識ミスでは残機を減らさない。
- 正解すると解説を表示。「次の問題へ」で次の20秒が始まる。
- 時間切れごとに残機を1減らし、正答確認後に次の問題へ。残機0（時間切れ3回）で終了。最終問題の時間切れが3回目なら残機0終了を優先し、それ以外は全問完了。
- 時計が進むのは手書き中と認識プレビュー中。画像化・推論・判定の待ち時間、解説中、画面切断中は停止する。
- 認識の書き直しでも残り時間は回復しない。不正解時は正答を公開せず、正解・時間切れ・中断後に公開する。
- 正解数・連続正解・正解率・送信回数を表示。スコア換算はしない。
- 本番体験の画像は学習データとして保存しない。認識の一時画像は処理後に削除する。

「漢字でGO!」の問題中心の表示・時間内の再回答を参考に、数学の手書き認識に合わせて設計した。原作の問題数・時間・進行を完全再現するものではない。
参照：[公式プレイページ](https://plicy.net/GamePlay/155561)、[開発者インタビュー](https://note.com/tkool_dev/n/n316ca7536c0c)。

## テストプレイ

1. テストプレイへ切り替え、問題文・ID・分野で検索する。全レベル検索と未確認フィルターも利用可能。
2. 問題へチェックを入れる。複数選択でき、選んだ順に出題する。
3. 時間制限なしで手書きし、「読み取りを確認」を押す。
4. 実際に送ったcrop済みPNGと認識した数式を比較する。原文LaTeXと処理時間も開ける。
5. 「この内容で回答」で初めて採点する。意図と違う認識なら書き直す。
6. 結果から同じ問題を再テストするか、次の問題へ進む。
7. 問題文・正答・表示を確認後、確認状況と本番候補を保存する。2画面構成ではこの管理操作は問題表示側にある。

確認状況は未確認・確認済み・要修正。本番候補にできるのは確認済みのみ。変更は `config/game_questions.json` に保存し、次のプレイから反映する。
516問中49問（各レベル7問）を、短い回答で試せる初期本番候補にした。残り467問もテストでは利用可能。
全516問の実筆精度や20秒で解けることは保証していない。初期候補を含め、展示PC・実際のペンでリハーサルする。

## 同意付きデータ保存

テスト中の認識プレビューまたは結果から任意に保存する。チェックは初期OFFで自動保存しない。
「書いた内容の正しいLaTeX」を画像に実際に書かれた内容へ修正し、画像との一致確認と保存同意を行う。
**問題の正答と、手書き画像の正しい転記は別物。算数として不正解でも、正しい転記付きの画像は保存できる。**

既定保存先は `data/custom`。`HMER_DATA_ROOT` を使用する場合は設定されたcustom_evalの場所に従う。

| 保存物 | 内容 |
|---|---|
| `images/<sample_id>.png` | モデルへ送った余白切り取り済み画像 |
| `strokes/<sample_id>.json` | 筆跡・筆圧・時刻・入力機器・Canvas寸法・crop座標・線幅 |
| `metadata/<sample_id>.json` | 問題ID・正答例・モデル出力・人の転記・同意・認識要求ID |
| `manifest.csv` | 画像パス・転記LaTeX・筆者コード等。既存の評価・学習前処理へ渡す一覧 |

筆跡座標はCanvasのCSSピクセルで、PNG上の座標にはcrop.x/yを引く。画像と筆跡は同じスナップショットを保存する。
`ground_truth_latex` は確認済み転記、`recognized_latex` はモデル出力、`reference_answer_latex` は問題の正答例。
`training_status=candidate_requires_dataset_review` として保存し、モデルの自動学習・重み更新は行わない。
学習前に誤ラベル・白紙・個人情報・重複を確認し、筆者単位でtrain/validation/testへ分割する。[再学習マニュアル](texteller-training.md) の管理CLIでレビュー・未使用データの選定・1回限りの追加学習を行う。学習利用には匿名のままではなく筆者コードが必要。氏名は使わない。
筆者コード `qa-synthetic-exclude` は開発検証用なので学習・精度評価から除外する。
氏名などを回答や筆者コードへ入れない。筆跡を含む `data/custom` はGit対象外。提供や移動は参加者の同意範囲内で行う。

## 問題データ・保守

- 元の7ファイルと旧50問は `config/question_sources/` に保存。ゲームの正本は `config/game_questions.json`。
- 固有IDは例 `d3-s2-r04-v01`。採番後に変更しない。
- `prompt` は日本語と `$…$` の数式を含む本文。HTMLは文字として扱い、数式だけKaTeXで表示する。
- 旧形式のquestion・question_latex・instructionは問題追加画面との互換用に保持する。
- sublevelは区分（全レベルで学年を意味するわけではない）、rankは段階。rankは解答時間や難易度の保証ではない。
- 分数のスラッシュ表記と一部の根号式の別表記を追加した。一般的な数学的同値判定ではない。
- インポーターの再実行は既定で拒否する。確認状況も初期化する明示オプション `--replace-bank` は通常セットアップ・更新で使わない。
- 進行の正本は `game/src/exhibition/Session.ts`。1画面版とDisplayで共用し、Controllerは受信状態を表示する。
- 旧Phaser画面と3コースの処理を削除し、問題表示はDOM/KaTeX、入力は独立Canvasに統一。長文を自然に折り返し、固定座標の中央ずれを避ける。
- 画面間通信は接続ID・通し番号・プレイID・問題ID・認識要求IDで古い結果や二重操作を拒否する。
- 問題配信はファイル更新に追従するキャッシュを使い、回答ごとの516問再解析を避ける。
- 既存の比較評価画面・モデル環境・収集データは維持する。

## 更新と設営

更新後はサーバー再起動と**両画面の再読み込み**が必要。新旧画面を混在させない。
同一PC・ブラウザー・プロファイル・Origin・sessionで使う。別PC間の同期には未対応。
問題編集・確認APIは認証なしのローカル運用用。不特定ネットワークへ公開しない。
