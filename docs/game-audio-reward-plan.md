# ゲーム音・達成演出の実装方針

## 結論

BGMは事前に制作した短いループ音源を同梱し、ブラウザーでは再生だけを行います。展示PC上で音を生成するモデルや新しい音楽ライブラリは追加しません。通信不要で、数式認識用GPUとも競合せず、音量と音質を本番前に固定できるためです。

ブラウザーは利用者の操作前に音声を自動再生できないことがあります。そのため、タイトルでは無音のままにし、「難易度を選ぶ」または「ゲームスタート！」を押した操作で音声を有効化します。これは [MDNのWeb Audio推奨事項](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices) と [自動再生ガイド](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay) に沿う設計です。

## 音の具体案

| 場面 | 音楽・効果音 | 狙い |
|---|---|---|
| 難易度選択 | 92〜100 BPM、木琴・マリンバ・柔らかいベース、32秒前後のループ | 明るいが急かさない。選択操作を邪魔する主旋律や歌声は入れない |
| 問題回答中 | 104〜112 BPM、同じ調性の軽いパーカッション、40〜60秒のループ | 無音の寂しさを解消し、計算を邪魔しない。低音と高音を控えめにする |
| 残り5秒 | BGMの音量は変えず、既存の柔らかい時計音を1秒ごとに追加 | テンポを急変させて焦らせず、時間だけを明確に伝える |
| 正解 | 150〜350msの柔らかい2音和音＋短いきらめき | 視覚演出と同時に成功を即時通知する |
| 連続正解 | 2連続目から半音ずつ上げ、5連続相当で打ち止め | 上達感を作りつつ、甲高くなり続ける不快感を防ぐ |
| 不正解 | 低めの短い木製打音。警告音・ブザーは使わない | 驚かせず、書き直しへ注意を戻す |
| 10問完走 | 1.5〜2.5秒の専用ファンファーレ | 通常の正解音と区別し、終了の達成感を作る |

ゲーム音は没入感やフィードバックに関係しますが、音の好みが合わない場合は体験を下げる可能性も報告されています。したがって「派手ならよい」とせず、現行の音量バーを常時利用できるようにし、実機で小学生を含む複数人に試聴して決めます。参考: [ambient/character soundsの実験研究](https://www.mdpi.com/2076-3417/14/2/583)、[BGMの好みとプレイヤー体験の実験研究](https://bibbase.org/network/publication/schubhan-karra-altmeyer-krger-likeitornotexploringtheimpactofdislikedbackgroundmusiconplayerbehaviorandexperience-2024)。

## 実装方式と採否

### 採用: 同梱音源 + HTML Audio

- `game/public/audio/` にループ可能なWAVまたはOGGと代替MP3を置く。
- 音源はGit管理し、オフラインで再生する。
- BGMと効果音は別音量にし、効果音中はBGMを約6 dB下げる。
- 正解音は再生速度を最大4半音分だけ変え、連続正解を表現する。これは現行実装へ先行反映済み。
- 音源名、作者、入手元、ライセンス、加工内容を `THIRD_PARTY_NOTICES.md` に追記する。自作・事前生成の場合も制作条件を記録する。

### 今回は不採用: Tone.jsなどの音楽ライブラリ

利点はテンポ同期、レイヤー切替、精密なスケジューリングです。一方、この展示で必要なのは2本程度のループ再生と短い効果音であり、依存・初期化・ブラウザー差を増やす効果の方が大きいため導入しません。将来、正解数に応じて楽器パートを動的に増減する段階になったら再検討します。

## 段階的な実装順

1. 既存の正解音を3案、選択BGMと回答BGMを各2案、完走音を2案制作する。
2. 同じスピーカー・本番音量で5人以上にA/B試聴し、「驚く」「計算を邪魔する」「達成感」の3項目を記録する。
3. 採用音を同梱し、BGM/SFX別の音量、画面切替時のフェード、バックグラウンドタブでの停止を実装する。
4. 10問通しプレイで音割れ、ループ継ぎ目、二画面からの二重再生がないことを確認する。音はモニター側だけで再生する。
