## 決まったことと今回の目的

対象は1人のプレイヤーと観客。モニターは「見る」、液タブは「操作する」。問題を液タブへ写さず、回答の生筆跡だけをモニターにも見せます。メモは液タブ限定です。色・書体・紙と藍の既存デザインを維持し、画面の役割を明確にします。

UIと通信を実装し、2026-10-30にTypeScriptテスト606件、本番ビルド、Computer Useでの1画面・2画面比較、回答筆跡同期、メモ非同期、GPUでのTexTeller認識を確認しました。物理液タブのペン固有挙動、同期遅延測定、ケーブル断を伴う復旧、長時間運転は未完了です。受入条件U01〜U12は、この証拠境界を保ったまま本番機で完了させます。

## 1. 設定画面と手書き画面を分ける動機

設定は「読む・選ぶ」、手書きは「広く書く・短い操作を確実に押す」という異なる仕事です。設定項目を常時残すと書ける面積が減り、プレイ中の誤操作も増えます。単なる演出のための画面分割ではありません。

| 状態 | 液タブの主役と操作 | モニター |
|---|---|---|
| 設定 | モード・難易度・テスト問題選択、遊び方へ | タイトル、選択状況、液タブ操作の案内 |
| ガイド | ルール説明、戻る、準備して開始 | 同じルールの要点、開始待ち。問題は隠す |
| 準備・開始予告 | 入力領域の準備、カウントダウン | 同期した開始予告。問題は隠す（実装済み） |
| 手書き | 回答／メモ切替、undo、全消去、読み取り | 問題＋回答筆跡、時間・残機 |
| 認識中 | 回答を固定、処理状態。時計停止 | 問題と回答を維持、認識中・時計停止 |
| 認識確認 | 回答画像と認識式、書き直す、回答する | 回答筆跡を維持、液タブで確認中・時計停止 |
| 誤答 | 短い状態通知、同じ用紙で再回答 | 不正解演出。正答は出さず同じ問題 |
| 正解・時間切れ | 「モニターで結果を確認」、次へ | 正誤・正答・解説。操作ボタンは不要 |
| 終了 | もう一度、設定へ | 正解数・正解率・終了理由 |
| 切断・エラー | 筆跡保持、理由、再接続・再試行 | 時計停止、回答は「同期停止」と明示 |

本番で問題本文や正答は液タブに出しません。テストの「問題選択」は例外で、開始前に問題を識別するための文言を表示できます。プレイ中はテストでも同じ分離を基本とします。管理用の問題レビューは折りたたんだ別作業として扱い、一般来場者のプレイに混ぜません。

## 2. 開始待機は「3秒待つ」だけではない

**採用済み・2026-10-23実装：初回は両画面の準備が整ってから3秒の予告を行い、予告中は問題を隠します。** 待機の役割は、レイアウト切替、ペンを置く場所の把握、問題へ視線を移す猶予です。準備待ちの時間をこの3秒に含めず、問題公開・入力解禁・計時開始を連動させます。

```text
液タブ「開始」
  → Displayが選択条件を検証し、プレイIDを発行
  → 両画面がガイドから入力／ゲーム面へ切替（問題はまだ描画しない）
  → Canvas寸法・描画先・モデル準備・接続版のready応答
  → Displayが開始予告を配信、両画面で予告
  → Controllerが入力可能の準備応答
  → Displayが問題公開・writing開始を確定、Controllerへ開始状態
  → 20秒計測（切断・未準備なら開始せず停止）
```

同一通信でも物理的に完全同時のpaintは保証できません。Display正本の開始とControllerの入力解禁のずれを測定し、入力できない時間が計時へ混入しないことを確認します。ローカルの`performance.now()`値をそのまま別タブの時計と比較せず、カウントダウンは表示用の進行情報として扱います。

開始ハンドシェイクは、Displayが`countdown`を配信し、ControllerがCanvasを表示して2回の描画機会を経た後に`controller-ready`を返し、Displayが予告を進める契約です。次問・再テストは秒数を固定せず、同じready受領後に開始します。物理paintと入力可能時刻の差は実機測定が必要で、見た目の予告だけで同期達成とは判断しません。

準備が長引いたら「入力画面の準備を待っています」、モデル待ちなら「認識モデルを準備しています」と理由を分け、中止／再試行を出します。ready上限は提案10秒、超過しても自動で出題しません。切断で予告を無効化し、再接続後は改めて準備確認します。古いreadyで開始しません。

次問も入力・空の用紙・問題公開の準備同期は必要です。一方、毎問3秒だとテンポを損ねるため、「初回3秒、次問1秒」を比較案とし、実機プレイで決めます。初回の3秒予告と問題非表示は採用済みですが、次問の予告時間まで確定したわけではありません。

## 3. 手書き中の構成案

推奨する基本構造です。割合は固定仕様ではなく、代表問題とviewportで検証する出発点です。

```text
モニター                           液タブ
┌────────────────────┐             ┌────────────────────┐
│ 問題番号・時間・残機 │             │ 回答  メモ │ 残り時間 │
├────────────────────┤             ├────────────────────┤
│                    │             │                    │
│   問題（主役）      │             │ 選択中の用紙       │
│                    │             │                    │
├────────────────────┤             ├────────────────────┤
│ 回答中の筆跡       │             │ 戻す 全消去 読み取り│
└────────────────────┘             └────────────────────┘
```

問題と回答コピーを別領域にし、筆跡が増えても問題を押し上げたり覆ったりしません。モニターに回答編集ボタンは置きません。コピーは装飾用の小窓ではなく、観客が読める大きさを確保します。

### レスポンシブのルール

- 横長モニターは上下配置を第一候補とし、HUDを除く高さの問題約60%・回答約40%から検証。横長の式では左右案も比較し、サイズだけで機械的に切り替えない。
- 低いウィンドウでも問題の最小可読サイズを先に守る。回答コピーを縮小しても線を極端に細くしない。収まらない式は最小文字サイズより小さく潰さず、構造を保ったスクロールで全文を読めるようにする。
- 回答用紙は縦横比を保ってcontain描画し、余白を許す。x/yを別々に伸縮して文字をつぶさない。問題の拡大演出は問題領域内だけに制限する。
- 液タブは手書き領域を最大化し、主要操作の位置を認識確認でもなるべく維持。48px以上を基本にし、サイズ不足をボタンの際限ない縮小で解決しない。
- 固定操作列に本文が隠れない余白、OS倍率・ブラウザーUI込みの高さ、全画面を解除した状態を検証する。全画面だけで成立させない。
- 回答用紙のアスペクト比が変わるリサイズでも既存の式を変形させない座標系を設ける。現行PadのCSS座標ごとの伸縮は、そのまま同期仕様に転用しない。

モニターのスクロールが必要になった場合も、モニターをクリックさせてはいけません。液タブに問題本文を写さず表示位置だけ動かす補助操作を設けるか、本番候補を表示可能な問題に限定するか、代表問題の試作時に決めます。無操作の自動スクロールだけに頼ると読んでいる位置が動くため、初期案にはしません。

## 4. メモは有用。ただし回答とは別のものにする

**方針：独立した回答用紙とメモ用紙を切り替え、メモは液タブ限定。** 常設2分割は比較候補ですが、書ける幅が減り、長い式や小さい液タブに不利なため初期案では選びません。ポップアップはペン操作・誤閉じ・下の内容の隠れが増えるため避けます。

| 操作・状態 | 回答用紙 | メモ用紙 |
|---|---|---|
| 切替 | 書いた内容を保持 | 書いた内容を保持 |
| 戻す・全消去 | 現在の用紙だけを対象 | 回答を消さない |
| 読み取り・採点 | 回答だけを対象 | 認識・採点へ送らない |
| モニター同期 | 生筆跡を表示 | 送信しない。「メモ中」の状態だけ通知可能 |
| 候補保存 | 同意・確認した回答のみ | 保存・学習・ログへの筆跡出力なし |
| 同じ問題の誤答・書き直し | 明示操作以外で消さない案 | 保持する案 |
| 次問・再プレイ・終了 | 次問前にクリア | 次の人へ残さずクリア |

メモ中も「回答／メモ」の選択状態を文字・背景・用紙見出しで明示。メモ中の主要操作は「回答へ戻る」とし、メモを提出できるように見せません。回答へ戻れば以前の回答とそのundo履歴が復元します。

計算も回答時間の一部なので、**メモ中・用紙切替でも時計は進む**案です。切替だけで時計を止めると、本番の制限を実質回避できてしまいます。既存の認識確認中停止は維持しますが、これは競技の公平性保証ではなく展示の体験設計です。

認識前に回答のスナップショットを固定します。認識／確認中はメモも編集不可とする初期案です。確認中に計算だけ続ける抜け道や画像・筆跡の不一致を増やさず、まず単純に運用します。ブラウザー更新後の用紙復元は別機能であり、初期案ではメモの永続化を約束しません。

## 5. 筆跡同期の技術案

protocol v4では`ink-snapshot`をControllerからだけ許可し、PairHubとブラウザーの双方で縦横比、有限な正規化座標、12,000点上限を検査します。回答は約40msごとの全体snapshotで送り、再接続時にも全体を再送します。メモPadには送信コールバックを持たせません。

責務は次のように分けます。

- `Session`：ゲーム進行の正本。設定・開始要求はControllerから受けてもDisplay側で条件検証して確定する。
- `ControllerInkStore`（新設案）：回答とメモの別履歴。認識用スナップショットの正本。ネットワークを待たず即時ローカル描画。
- `InkPublisher` / `InkReplica`（新設案）：回答の送信と読取専用コピー。SessionのHUD更新とは独立。
- `PairHub`：許可したメッセージを中継し、サイズ・役割・版を検証。ゲームや筆跡の永続正本にはしない。

提案メッセージは`ink-reset / ink-append / ink-undo / ink-snapshot / ink-resync-request`。回答の文書ID・revision・stroke ID・run ID・question ID・接続世代を付け、古い問題や消去前の差分を拒否します。順序が欠けたら全体を要求し、古い筆跡へ継ぎ足しません。

用紙の安定した論理座標と寸法・線幅を基準に、描画先では単一スケールと余白で変換します。同期用座標の正規化と、既存保存形式のCSS座標は別物です。保存形式を変える場合はschema版と変換を追加し、既存画像とcrop座標の対応を壊しません。

送信は提案20〜30Hzで点列をまとめ、Pointer EventsのたびにPNGや全履歴を送りません。active strokeも送るため、ペンを離すまで表示されない方式にはしません。途中経過は間引けてもundo/clear/endは落とさず、混雑時は古い差分を延々蓄積せず最新snapshotへ収束させます。

再接続時はControllerの回答snapshotを送り直します。メモは送らず、認識・提出・保存要求も再実行しません。1MiBの現行上限を超える用紙には点数上限または分割snapshotが必要で、上限と切捨て方は実装前に決めます。無制限の受信・描画や静かな欠落は認めません。

回答を消すとコピーも消えます。メモへ切り替えてもコピーは最後の回答を維持します。切断時は古いコピーを「同期中」のように見せず、「同期停止」と表示。次問へ進む前に別文書IDへ切り替え、前問の手書きが新問の回答として残らないようにします。

## 6. 実装・レビューの受入条件

以下は今後実行する検査であり、今回の合格結果ではありません。

| ID | 試験 | 期待結果 |
|---|---|---|
| U01 | 設定→開始→回答→結果→再プレイを液タブだけで操作 | モニターのクリック不要。問題・解説は液タブのプレイ領域に出ない |
| U02 | 開始・次問の準備遅延、切断、古いready受信 | 入力不可のまま計時しない。問題の先行表示なし |
| U03 | 点・連続線・undo・clear・用紙切替 | 両画面の回答一致。メモはネットワークに載らない |
| U04 | 長い筆跡、遅延、切断復帰、次問後の古い差分 | ローカル入力を妨げず、全体再同期で収束。別問の線は表示しない |
| U05 | 回答とメモに別の式を書き、認識・保存 | 回答だけがPNG・crop・筆跡・ラベルへ対応。メモ混入0件 |
| U06 | 誤答、認識失敗、判定失敗、書き直し | 必要な筆跡を保持、残り時間は復活せず、意図しない再送なし |
| U07 | 初期・白紙・認識・確認・正解・時間切れ・残機0 | 次の操作と停止理由が分かる。モニターで結果を見る導線 |
| U08 | 1920×1080 / 1366×768 / 1024×768 / 768×1024 / 320×568、倍率125〜200%、全画面解除 | 問題と回答が重ならず、必要操作に到達可能。狭い画面のスクロールは隠さない |
| U09 | 長文・短い数字・分数・行列・長い回答 | 問題を可読サイズに保ち、コピーは比率維持。式の欠落なし |
| U10 | ペン・マウス、キーボードの切替/ボタン/フォーカス | 誤タップ・隠れた操作・フォーカス喪失を記録して修正 |
| U11 | 展示PC CPU/GPUで筆跡同期と推論を同時実行 | 入力追従、同期遅延p50/p95、最大メッセージ、長時間メモリを測定 |
| U12 | 回答／メモの全消去と中断の配置 | 全消去は現在の用紙へ即実行。通常の1画undoは維持するが全消去の取り消しは追加しない。中断は手書き・提出操作から離し、終了後の復元は提供しない |

同期遅延はまず同一PCでp95 100ms以下を仮目標にし、実測前の保証にはしません。入力の体感遅延はネットワーク遅延と別に測ります。タイマー開始のずれ・入力不可時間も別指標にします。

実装単位ごとに自動検査。UIは初回の両画面・代表サイズをまとめてレビューし、一括修正後に確認します。新しい問題を無限に探し続けるのでなく、未解決事項を記録してユーザーへ返します。最終的には実機ペンと初見利用者のテストを行い、閲覧画面だけの確認で完了としません。

## 7. 設計レビューで先に見つけた落とし穴

- **操作集約と正本移管の混同**：Controller操作に変えてもSessionを2つ作らない。
- **開始前の問題漏れ**：現在のguide snapshotにはquestionが入る。CSSで隠すだけでなく表示用データの扱いを見直す。公開アプリの不正対策を保証するものではない。
- **2枚のCanvasを隠したときのresize**：0幅・0高さで保存済み座標を壊さない。切替前後で同じ画像になる回帰検査を追加する。
- **メモのundoが回答を消す事故**：履歴と操作対象を別オブジェクトにする。
- **同期画像が認識用データになる事故**：Displayのコピーは表示専用。認識・保存の正本に逆流させない。
- **問題を大きくする演出が回答欄を覆う**：領域の最大寸法で制限し、全画面以外も検証する。
- **観客への露出と保存同意の混同**：開始案内で回答筆跡がモニターへ表示されることを伝える。学習保存への同意とは分ける。氏名等を書かない案内を添える。

## 8. 次の確認事項

1. 次問の予告時間を短くするか。比較試作してテンポと操作準備の両方で決める。
2. 回答／メモ切替の実機での書きやすさ。初期案は切替式で、常設分割はその後の比較対象。

メモの公開範囲は「液タブのみ」で確認済みです。メモの保持・時計・認識中編集の詳細は本書の推奨案であり、完成UIとテスト結果を見て再確認します。

## 9. ゲームで馴染みのある仕組みを使う判断基準

ユーザー方針：開始予告に限らず、ゲームで馴染みのある仕組みを各場面で検討する。「何が起きるか分かる」「押した結果が分かる」「次の行動へ自然に移れる」に寄与するかで判断します。対戦向けの公平性やランキングを導入する意図ではありません。

2026-10-22の追加合意：全消去・中断の復元機能は追加せず、下記の他のUX案は方向性として了承されました。初回3秒予告は確定、その他はこの方向で詳細を詰めます。秒数・音量・演出・同期手順の細部まで一括確定したものではなく、既存機能と未実装案も区別します。

| 場面 | 仕組み・状態 | UXへの寄与 | 注意点／採用判断 |
|---|---|---|---|
| 初回開始 | 3・2・1の開始予告 | ペンと視線の準備ができる | 実装済み。両画面ready後、問題は予告後に公開。実機時差は未測定 |
| 初見の操作 | 最初の入力時に短い「答えを書き、読み取りを確認」案内 | ルール説明を覚えていなくても行動できる | 方向性了承・詳細検討。毎問繰り返さず、問題や書いた線を覆わない |
| 操作受付 | ボタンの押下反応、認識開始直後の受付表示 | 受け付けたか不安で連打するのを防ぐ | 一部既存。次期も待たず表示し、採点成功とは区別する |
| 残り時間 | 最後の数秒を文字・控えめな音で予告 | 時間切れが突然に感じられない | 既存の警告を次期レイアウトでも確認。音だけに依存せず、時計停止中は警告しない |
| 誤答 | 短い誤答表示から同じ問題の再回答へ戻す | 何度も挑戦できるルールが伝わる | 再回答は既存。方向性了承・演出詳細は検討。長く入力を塞いだり、演出中だけ時間を浪費させない |
| 正解・時間切れ | 結果を見せてから手動で次へ | モニターを見る間と解説を読む時間を確保 | 現行の手動進行を維持する方針。自動で次問へ飛ばさない |
| 次問 | 次の問題番号の予告＋入力領域の準備 | 用紙が切り替わったことを理解できる | 方向性了承・時間は検討。初回と同じ3秒を機械的に繰り返さない |
| 全消去・中断 | 全消去は即実行。中断は手書き・提出操作から離して配置 | 操作を増やさず、配置で中断の誤操作を減らす | 採用方針。全消去の取り消し・終了後のプレイ復元は追加しない。必要なら中断時だけ確認するが、その要否はレイアウトレビューで決める |
| 接続復帰 | 「再接続しました」＋再開できる状態の案内 | 止まった後にいつ書けばよいか分かる | 方向性了承・詳細検討。準備確認なしに計時を再開せず、毎回3秒必須にはしない |
| ゲーム終了 | 終了理由・結果・再プレイの明確な区切り | 達成感と次の行動を両立する | 結果表示は既存。演出の方向性了承。スキップ可能にし、長い強制待機を増やさない |

演出を採用する前に、目的・開始終了条件・入力可否・時計の扱い・切断時の扱いを状態表へ記載します。待機時間を増やすなら「何を準備する時間か」を説明できることが条件です。数字の予告は文字でも伝え、効果音を切っても理解可能にし、動きを減らす設定では大きなズームや点滅を避けます。

検証では「初見で次の操作が分かったか」「意図しない連打が減ったか」「演出が入力・問題閲覧を妨げなかったか」を観察します。主観的な豪華さだけを改善の根拠にせず、展示のテンポと再プレイの負担も記録します。
