# 数学でGO 問題追加ガイド

現行は516問・2モード。問題選択・確認状況・本番候補・学習候補保存は [現行マニュアル](two-mode-exhibition.md) を参照してください。
追加した問題は既定では未確認・本番候補OFFとなり、テストプレイで選択できます。確認後に明示的に本番候補へ追加してください。

ゲーム問題の正本は `config/game_questions.json` です。専用画面またはJSON編集で追加するとBackendが検証・配信します。Frontendへ同じ問題を書き足す必要はありません。本番への追加はテストプレイで確認後に明示的に行います。
検証用には、問題JSONのコピーを環境変数 `HMER_QUESTION_BANK` に指定してサーバーを起動できます。読む・登録・確認状況更新・採点が同じコピーを参照します。未指定時は従来の正本を使います。

## もっとも簡単な追加方法

サーバー起動中に次のURLを開きます。

```text
http://127.0.0.1:8000/questions/editor
```

問題の数式、読み上げ用テキスト、指示、カテゴリ、難易度、正答候補、解説を入力して「この問題を登録」を押します。管理IDは空欄でも自動生成されます。登録内容は `config/game_questions.json` へ保存され、次にテストプレイを始めたときから選択できます。

この画面は問題作成者向けです。展示中のプレイヤー画面にはリンクを表示せず、運用担当者が直接URLを開きます。

## 1問の形式

```json
{
  "id": "differentiate-cubic",
  "question": "f(x) = x³",
  "question_latex": "f(x)=x^3",
  "instruction": "f(x)を微分しなさい",
  "answer": ["3x^2", "3{x}^2"],
  "description": "x³の導関数は3x²です。",
  "difficulty": 4,
  "category": "微分"
}
```

| 項目 | 必須 | 内容 |
|---|---:|---|
| `id` | はい | 問題を識別する英小文字・数字・ハイフンの固有ID。一度公開したIDは変更しない |
| `question` | はい | 数式表示が失敗した場合や読み上げで使う、人が読める問題文 |
| `question_latex` | はい | 画面に整形表示するKaTeX互換LaTeX。外側の `\[` `\]` は付けない |
| `instruction` | はい | 「計算しなさい」など、プレイヤーが何を答えるか |
| `answer` | はい | 受理するLaTeX文字列の配列。先頭が結果画面の代表正答 |
| `description` | はい | 正答後に表示する短い解説。1～2文を目安にする |
| `difficulty` | はい | 1～7の整数 |
| `category` | はい | 集計と出題バランスに使う分類名 |

## 難易度

1. 小学校低学年
2. 小学校高学年
3. 中学校
4. 高校
5. 大学・理工系
6. 大学院
7. 超上級・専門数学

本番体験は選択したレベルの確認済み本番候補から、来場者が設定した1〜7問を重複なしで抽選します。既定は7問です。テストプレイは任意の問題を選択し、レベルをまたいでも利用できます。

## 正答候補の考え方

- `answer[0]` には、プレイヤーへ見せたい最も自然な表記を書く。
- 並べ替えや省略記号など、認識で実際に出やすく数学的にも許容する表記だけを2件目以降へ追加する。
- 現在の判定は空白、外側の数式区切り、代表的なLaTeX表記を正規化した後の一致です。一般的な数式の同値変形までは判定しません。
- 例: `3/4` と `\frac{3}{4}` は候補へ両方登録する。`x(x+1)` と `x^2+x` は現段階では自動的に同一とは判断されない。
- 広すぎる候補は誤答を正解にするため、「モデルが出しそう」という理由だけでは追加しない。

## JSONを直接編集する場合

1. `config/game_questions.json` の `questions` 配列へ1問を追加する。
2. `question_latex` がKaTeXで意図どおり表示されることをゲーム画面で確認する。
3. 次の検証を実行する。

```powershell
.\.venv\Scripts\python.exe scripts\validate_game_questions.py
.\.venv\Scripts\python.exe -m pytest tests/test_game_questions.py
```

4. 代表正答と各別表記を手書きし、読み取り結果が正答になることを確認する。
5. 明らかな誤答も1件試し、誤って正解にならないことを確認する。

JSONの構造をエディタで検査したい場合は `config/game_questions.schema.json` を利用できます。起動時の最終検証はBackendの `load_questions` が担当し、不正なID、空欄、難易度範囲外、空の正答配列を拒否します。

## レビュー時の確認事項

- 問題文だけで答える対象が一意に分かるか。
- 定積分の上下限、極限の近づく値、行列の行列構造がLaTeX上で見えるか。
- 代表正答は簡潔で、解説と矛盾していないか。
- 難易度とカテゴリは既存問題と比べて妥当か。
- 個人名、学校名、端末固有パスなどを含んでいないか。
