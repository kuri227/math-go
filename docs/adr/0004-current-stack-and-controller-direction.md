# ADR 0004：現行構成の追補と2画面コントローラーの次期方針

- 日付：2026-10-22
- 状態：採用・2026-10-23実装。実機検証は継続
- 関連：[要件全体](../product-and-roadmap.md) / [次期UX案](../dual-screen-controller-ux.md)

## 背景

ADR 0001のPhaser構成、ADR 0003のBroadcastChannelは採用当時の記録です。その後DOM化とWebSocket移行が実装されましたが、ADRだけ読むと現行構成を誤解します。原文を消さず、更新関係をここで示します。

## 現行で置き換わった決定

- ADR 0001のPhaser中心構成は、TypeScript / Vite / DOM / KaTeX＋独立Canvasに置換済み。自然な文章・フォーム配置、数式fit、固定座標とDOMの二重管理を減らす方向です。
- ADR 0003のDisplay/Controller分離とDisplay進行正本は継続。BroadcastChannelは同一PCのWebSocketリレーに置換済み。背景タブのheartbeat判定への依存を除きます。
- ADR 0002のJSON問題正本は継続。ただし現行はファイル変更に追従するキャッシュと書込検証・lockを利用。配布はRelease展開でなくclone/pull方針です。

実装上の制限は [現行アーキテクチャ](../architecture.md) を参照。別PC・対戦・永続ゲームセッションを追加したわけではありません。

## 合意と実装

2画面ソロを標準にし、問題・正答・解説はモニター、全ユーザー操作は液タブへ集約します。回答の筆跡は両画面へ表示、メモは液タブ内だけで扱います。操作移管・筆跡同期・独立メモは通信版v4で実装しました。

初回は両画面準備後に3秒の開始予告を行い、予告中は問題を隠します。Controller ready受領後に予告を進め、問題公開・入力解禁・計時開始を連動させる状態を実装しました。

追加合意（同日）：全消去は即実行し、中断は手書き・提出操作から離します。全消去の取り消し・終了後のプレイ復元は実装対象外。必要な場合だけ中断確認を検討します。他のゲーム的UX案は方向性として了承されており、具体的な演出と時間はUX案で詰めます。

## 提案であり未確定のこと

未確定なのは次問へ演出的な秒数を加えるか、Display領域比率の実機調整、全体snapshot方式の同期遅延・処理量目標、効果音などです。実装は次問をready受領直後に開始し、筆跡を縦横比付き正規化snapshotで扱います。詳細と未検証範囲はUX文書へ集約します。

## 選ばないこと

- 問題を液タブへ複製して1画面で体験を完結させる。
- 操作の移管に伴って、進行正本をControllerとDisplayへ二重化する。
- メモを無断で同期・認識・学習保存する。
- 筆跡表示の追加を理由に、クラウド・遠隔対戦・動画配信を導入する。

## 影響と検証

通信版・メッセージ検証・入力履歴・画面遷移の変更が必要です。既存学習データ形式を暗黙に変更しません。小さな実装単位で両画面・resize・切断復帰・CPU負荷を検証し、未確定事項はユーザー確認後に採用へ更新します。
