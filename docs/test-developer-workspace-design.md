# テスト・開発者用ワークスペース再設計

更新：2026-11-04。第1段階（問題選択ワークスペース）は実装・実機確認済みです。対象は問題選択・テスト開始・問題検証・将来のランキング管理であり、来場者向け展示画面のデザインは変更しません。

## 現在の実装状態

- 本番の難易度設定と、問題検索用の難易度条件を分離した。
- 問題ID・分野・問題文の検索、難易度、確認状況、本番候補で絞り込める。
- 一括選択・解除は全526問ではなく、現在表示している問題だけを対象にする。
- 条件を切り替えても選択を保持し、総選択数と表示中の選択数を分けて表示する。
- デスクトップは3列、狭幅は2列または縦積みとし、ページ全体ではなく各一覧を内部スクロールさせる。
- 選択中一覧から個別解除・全解除でき、0問ではテスト開始を無効にする。
- 958×854の実ブラウザーで、516問表示、LEVEL 1の36問一括選択、LEVEL 2へ変更後の選択保持を確認した。

未実装なのは、複数難易度の同時指定、条件チップ、問題行の詳細展開、出題順変更、ランキング管理です。これらは現行の問題テストを妨げない追加改善として扱います。

## 目的と利用者

この画面は来場者ではなく、問題を検証する開発者・当日スタッフが使います。526問から条件に合う問題を探し、複数選択し、出題順を確認してエンドレステストへ進むことが主作業です。

展示画面と同じ「大きな余白で一つの操作へ集中させる」構成は使いません。操作密度、一覧性、選択状態の見通しを優先した全幅の管理ワークスペースとします。ただし色、文字、ボタン、フォーカス表現は既存のデザインシステムを再利用します。

## 現在の問題

1. 本番用の難易度選択と、問題一覧の絞り込みが同じプルダウンを共有し、設定なのか検索条件なのか分かりにくい。
2. 「全レベルから探す」のチェックで難易度プルダウンが実質無効になるが、画面上では両方が有効に見える。
3. 「全516問を選択」は、検索・難易度・未確認フィルターを無視して全データを選ぶため、利用者の直前操作と一致しない。
4. 一覧は高さ360pxの細い領域へ閉じ込められ、全画面時に周囲の余白が増える一方で、問題一覧は広がらない。
5. 1行あたりの問題表示が大きく、516問を走査する画面として情報密度が低い。
6. 選択済み問題が一覧のチェック状態にしか現れず、別の条件へ絞ると何を選んだか、どの順に出題されるか確認しにくい。
7. 「問題を探す」「選択を組み立てる」「テストを開始する」の階層が弱く、主要操作が長い一覧の下へ離れる。

## 採用する画面構成

タイトル画面の「テスト・開発者用画面」から、展示設定とは別の専用ワークスペースを開きます。初期実装では同じアプリ内の専用ビューでも構いませんが、DOMと状態は本番の難易度設定から分離します。将来 `/developer` へ独立させられる責務にします。

デスクトップと横向き液タブでは、次の3領域を画面幅いっぱいに配置します。

| 左：絞り込み | 中央：検索結果 | 右：選択中・開始 |
|---|---|---|
| 難易度、確認状況、本番候補、検索、条件解除 | 一致件数、全選択、問題一覧、個別チェック | 選択数、出題順、個別削除、全解除、テスト開始 |

- 左列は240〜280px程度の固定幅、右列は280〜360px程度、中央を残り幅へ広げます。
- 画面全体ではなく、問題一覧と選択中一覧をそれぞれ内部スクロールさせます。
- 全画面時は中央列の問題文プレビューと右列の選択一覧が広がり、空白だけが増えないようにします。
- 縦画面では「絞り込み」「検索結果」「選択中」を上から積みます。選択中は折りたたみ可能な下部パネルとし、「選択N問・テスト開始」は常に確認できるようにします。

## 絞り込みと一括選択

本番設定で使う難易度プルダウンは、この画面では使いません。問題検索専用の条件として次を用意します。

- 難易度：`すべて / LEVEL 1〜7`。現在は単一選択。複数レベルの同時指定は追加改善とする。
- 確認状況：`すべて / 未確認 / 確認済み / 要修正`。
- 本番候補：`すべて / 候補のみ / 候補外のみ`。
- キーワード：問題ID、分野、問題文を横断検索。
- 「条件をすべて解除」を用意する。適用中条件のチップ表示は追加改善とする。

一括操作は、必ず現在の絞り込み結果を対象にします。

- 主操作：`絞り込み結果36問をすべて選択`。
- 絞り込み結果の一部だけ選択済み：チェックは混合状態で表示する。
- 全件選択済み：`絞り込み結果36問の選択を解除`へ切り替える。
- 全516問の選択は通常操作から外し、必要なら補助メニュー内の`全問題を選択…`から件数確認後に実行する。
- 選択済み問題は絞り込み条件を変更しても保持する。条件外にある選択数を`選択23問（表示中12問）`のように明示する。

## 問題一覧と選択中一覧

問題一覧はカードの縦並びではなく、走査しやすいコンパクトな行を基本とします。

- 行頭：選択チェック。
- 固定情報：問題ID、LEVEL、分野、確認状況、本番候補。
- 主情報：問題文を1〜2行で省略表示。数式はKaTeXを維持する。
- 行を展開すると、問題全文・正答・解説・制限時間・問題点報告件数を確認できる。
- 行全体をクリックしてもチェックを切り替えられるが、展開ボタンやリンク操作とは競合させない。

右列の「選択中」には出題順で問題を表示します。

- 各行から選択解除できる。
- 現在はデータ側の出題順を保持する。上下ボタンによる順序変更は追加改善とし、必要性が確認できてからドラッグ並べ替えを検討する。
- `選択をすべて解除`は右列に置き、絞り込み結果の解除と区別する。
- 0問時は、開始ボタンを無効化するだけでなく「中央の一覧からテストする問題を選択してください」と表示する。

## テスト開始と状態

右列下部に開始領域を固定し、`選択N問をエンドレステスト`を主要ボタンとします。モデル準備中・2画面未接続・0問選択では、ボタン付近に原因と次の操作を表示します。

必要な状態は次の通りです。

- 読み込み中：一覧の枠を保ったスケルトンまたは進捗表示。
- 0件：条件と一致する問題がないこと、条件解除ボタン。
- 選択0件：選び方の短い案内。
- 条件外の選択あり：保持していることと件数を明示。
- 516件表示：入力操作を妨げない性能を保つ。必要なら行の仮想化を導入する。
- 保存・通信エラー：選択状態を消さず再試行できる。
- キーボード：フィルター、一覧、選択中、開始の順に移動し、フォーカスを視覚表示する。

## ランキング管理との境界

同じ「テスト・開発者用画面」入口に、上位タブとして次を置く予定です。

1. `問題テスト`：本書の問題選択ワークスペース。
2. `問題・学習データ`：確認状況、問題点報告、同意付き学習候補。
3. `ランキング管理`：記録検索、表示名編集、非表示、削除、CSV出力、同期待ち確認。

初期実装では問題テストだけを再設計し、ランキング管理の未実装タブを表示しません。空の管理画面や「準備中」を本番UIへ置かない方針です。

## 実装順と受入条件

1. 問題検索状態を本番難易度設定から分離する。
2. フィルター結果に対する全選択・解除へ変更し、件数の自動テストを追加する。
3. 全幅3列レイアウトと縦画面の積み上げレイアウトを実装する。
4. 選択中一覧を追加する。出題順変更は追加改善として分離する。
5. Computer Useで通常ウィンドウと狭幅2列表示を検証する。会場機材での全画面・縦長液タブ確認は設営時の受入試験として残す。

受入条件は、検索条件を変更しても選択が意図せず失われないこと、一括操作の対象件数がボタン文言と一致すること、全画面で主要領域が中央の細い列に留まらないこと、0〜516件・0〜516件選択の状態を操作できることです。

## 変更しないもの

- 来場者向けタイトル、難易度選択、ゲームプレイ、結果画面。
- 本番10問固定、難易度別時間、残機、テストのエンドレス進行。
- 問題データ形式、問題ID、確認状況、本番候補フラグ。
- 2画面時の「問題はモニター、回答とメモは液タブ」という役割分担。
