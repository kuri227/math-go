# 数学でGO ゲームUX・正答判定検証レポート

検証日：2026-10-03

対象：Phaser + TypeScript + Viteフロント、FastAPI、TexTeller 3.0

## 結論

モデル準備完了後の提出体験は、現PC・単一利用者・ローカル接続ではゲームのテンポを損なわない。2026-10-03の再計測では独自Web入力9件の認識APIはP50 208.9ms、P95 362.3msで、判定APIはP95 2.45msだった。ブラウザで実際に `2x+3` を手書きしたEnd-to-End確認では、画像化12.6ms、推論351.3ms、判定4.6ms、提出から表示まで385.9msだった。

一方、モデル初期化は8.15秒かかる。ページ表示と同時に先読みし、準備中は提出ボタンを理由付きで無効化する現方式は必須である。入力データが9件・1筆者のみのため、文化祭本番可否の最終判断には50〜100件以上、複数筆者、想定端末での再評価が必要である。

## 実装した判定

`POST /api/v1/judgements` を追加した。問題IDと認識LaTeXを受け取り、表示上の差を正規化したうえで問題ごとの許容表記と照合する。

- 受理例：`\[3 + 2x\]` と `3+2x`
- 非対応：任意の数式変形、定義域を含む数学的同値性
- 判定方式名：`normalized_alias`

一般の数学的同値性とHMERモデルの認識精度を混同しないため、この段階では意図的に保守的である。

### ブラウザ実操作

1問目「`f(x)=x²+3x` を微分」に対し、Canvasへ `2x+3` をマウスで描画した。

- 認識：`\[2x+3\]`
- 判定：正解
- 画像化：12.6ms
- 推論：351.3ms
- 判定：4.6ms
- 提出から判定表示：385.9ms
- PNG：5.4KB

その後、次問への進行でスコア100、連続1、残機3が反映された。スキップ3回で残機0となり、終了画面へ遷移した。終了画面は正解数1/4、平均応答386msを表示した。

## UX判定

目標をP50 1,000ms以下、許容P95 2,000ms以下、3,000ms超を阻害線とした。今回の温間状態はP50・P95とも目標内で、ブラウザ実操作も0.4秒未満だった。この条件では応答待ちがゲーム体験を損なう可能性は低い。

ただし、以下は別扱いにする。

- 初期化8.15秒：プレイ開始前の先読みで隠す。準備完了前は提出不可。
- 認識ミス：結果を確定する前に書き直せるため、即時失点させない。
- 同時利用：現在はモデルごとに1本の推論ロックがあり、複数同時提出では待ち行列が伸びる。文化祭で複数端末をつなぐ場合は負荷試験が必要。
- 長い数式：公開HWEのP95はTexTeller 1,204.8msで、独自9件より重い。複雑式では1秒を超える前提で演出が必要。

## 画像二値化の判断

既存9件のA/B結果では、1-bit PNGは平均サイズを大幅に縮小した一方、認識結果は全件同一で、推論時間の改善は一貫しなかった。ローカル接続では送信サイズよりモデル推論が支配的なので、現時点ではフルカラーPNGを既定のままにする。LAN帯域や保存量がボトルネックになった時に再検討する。

## ブラウザレビューと改善

### 1回目

- デスクトップで問題、Canvas、提出が同じ視界に入り、正答から次問まで進めた。
- 390px幅で提出が編集操作より先に置かれ、Canvasの書込み面積も確保できた。
- 問題進捗、スコア、連続数、残機、モデル状態を常時確認できた。
- 問題：結果へ即スクロールすると舞台上の正誤演出を見逃す。

### 改善

- 正誤演出を約780ms表示した後に結果へスクロールするよう変更。
- 進行線を「完了済み0問」ではなく現在問題を含む比率へ変更。
- 終了時の舞台高さを縮め、不要な空白を削減。
- `Q` スキップ、`Enter` 提出／次へを追加。

### 2回目

- 改善版を再build・再読込し、同じ `2x+3` を再度手書きして正解判定まで確認した。
- 提出後は画面位置を保ったまま大きな正解演出が見え、約0.8秒後に結果比較へ移動した。
- `Q` キーで次問へスキップし、残機3から2へ変わることを確認した。
- 進行線が1問目から表示され、スキップ操作にも `Q` のヒントが見えることを確認した。
- production build、型検査、全ユニットテストは再実行後も成功し、console error / warningは0件だった。
- 固有作品の画像・音・キャラクター・ロゴは利用していない。

## 残るリスクと次の検証

1. Web実入力を50〜100件へ増やし、複数筆者・マウス・ペン・タッチを含める。
2. 行列、極限、積分、分数、上下付きの失敗率を個別計測する。
3. 文化祭本番PCで30分以上の連続プレイとVRAM推移を確認する。
4. 同時2〜4端末の待ち行列とP95を測る。
5. 30秒チャレンジの難易度と速度ボーナスは暫定値であり、プレイテストと次のプレイ前後UX要件で再調整する。
6. SymPy等の同値判定を追加し、HMER評価指標とは別に記録する。
