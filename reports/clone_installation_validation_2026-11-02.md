# clone後の導入文書検証（2026-11-02）

## 目的

技術知識の少ないWindows利用者が、READMEと導入ガイドだけを入口にGitHubからcloneし、初回セットアップと1画面・2画面の確認へ進めるかを検証した。

## 検証環境

- Windows 11 x64
- Git 2.46.1.windows.1
- Python 3.10.5（64bit）
- Node.js 22.17.1
- pnpm 11.25.0
- 検証日: 2026-11-02

## 実施内容と結果

1. `https://github.com/kuri227/math-go.git`から一時フォルダーへ実際にcloneした。公開リポジトリの取得は成功した。
2. clone直後にREADME、導入ガイド、運用マニュアル、CPU/GPU別のsetup・startスクリプト、環境確認、`package.json`、`pnpm-lock.yaml`、固定Python依存が存在することを確認した。
3. clone直後の文書リンク検査とWindows PowerShell 5.1互換性テストは4件成功した。
4. clone直後のCPU版preflightでは、Python・OS・空き容量はOKだった。venv、モデル、画面ビルドは初回セットアップ前なのでWARNとなり、未導入状態を正しく識別した。
5. 導入ガイドの外部取得先を確認した。Python 3.10.11ページ、Python 3.10.11 64bitインストーラー、Node.js 22.17.1 64bit MSI、pnpm 11.25.0の公式npmレジストリはいずれもHTTP 200だった。
6. 現在の検証PCで`git --version`、Python 3.10.5、Node.js 22.17.1、pnpm 11.25.0が実行できることを再確認した。
7. 修正後は文書・PowerShell互換性・配布スクリプトの対象テスト14件、現行18文書のローカルリンク検査、`git diff --check`が成功した。

## 発見して修正した点

- 起動スクリプトは指定なしでは2画面用Displayを開くが、導入ガイドはタイトル画面が開く前提だった。初回確認には`-SingleScreen`を付け、2画面確認では停止後に指定なしで再起動する手順へ修正した。
- 既定ブラウザーがChrome／Edgeでない場合と、自動で画面が開かない場合のURL入力手順を追加した。
- 初回セットアップはモデル以外の依存も含めて数GBを取得し得ること、正常完了の目印、重複実行を避けることを明記した。
- 停止はPowerShellを閉じるだけでなく、`Ctrl+C`後にコマンド入力へ戻ったことを確認する手順へ統一した。
- 実検証したPython 3.10.5と、導入時にダウンロードを案内するPython 3.10.11（64bit）を区別して明記した。
- 導入ガイドと開発ガイドが文書リンク自動検査の対象外だったため、現行文書の検査対象へ追加した。

## 検証境界

数GBの依存とモデルを同じPCへ重複導入する完全な初回セットアップは、この監査では再実行していない。既存のCPU/GPU環境での起動・認識実績、固定依存、セットアップスクリプトの回帰テスト、clone直後のpreflightを組み合わせて確認した。別PCでは導入ガイドどおりに初回セットアップを最後まで行い、`[FAIL]`がないことと1問の認識を確認する必要がある。
